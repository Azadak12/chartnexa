## What is hosted, and what is not
| Area | Hosted pilot setting | Notes |
|---|---|---|
| Database | Neon PostgreSQL | TLS required (`?sslmode=require`), enforced at start-up |
| Files, thumbnails, assignment files, video | `STORAGE_DRIVER=postgres` | Bytes live in the Neon database (table `storage_objects`), never public; every read goes through signed links. Sized for a pilot: Neon's storage limit and the 1 GB column limit apply. A real object store is decision Q32 |
| Video | `VIDEO_PROVIDER=direct` | The uploaded MP4 with ranged, signed streaming. No transcoding or adaptive streaming; a video platform is decision Q09 |
| Payments | `PAYMENT_PROVIDER=disabled` | Nobody can buy (clear message). Admins and Managers give students access under *Students and access*. Real payments are ADR-0008 and App Store rules |
| Malware scanning of lesson files | `SCANNER=none` with `FILE_UPLOADS=disabled` | Uploading lesson files (PDF, etc.) is off, so nothing goes unscanned. To turn it on run a ClamAV daemon (clamd, for example the `clamav/clamav` image as a Render private service) and set `SCANNER=clamav`, `CLAMAV_HOST`, optionally `CLAMAV_PORT`; remove `FILE_UPLOADS`. A scanner outage rejects uploads, never accepts them |
| Email | `MAILER_DRIVER=resend` | Needed for sign-up verification and password reset. Verify your sending domain in Resend |

The production checks are unchanged: `local` storage, the `test` video and payment adapters, the dev mailer, a missing encryption key and the two-step shortcut are all still refused in production. Video thumbnails, video and assignment attachments are checked by content type, not by the scanner (as before).

## Accounts and values you need
1. **Neon:** create a project (region near Render). Copy two connection strings: the **pooled** one (host contains `-pooler`) and the **direct** one. Both end with `?sslmode=require`.
2. **Resend:** an API key and a verified sending address.
3. **Secrets you generate yourself:**
```bash
openssl rand -base64 32   # MFA_ENCRYPTION_KEY: store a copy somewhere safe
```
`CURSOR_SECRET`, `ACCESS_TOKEN_SECRET` and `METRICS_TOKEN` are generated by Render from the blueprint.

## Render settings (exactly)
Use the blueprint (New → Blueprint → this repository, file `render.yaml`) or enter by hand:

- **Runtime:** Node, repository root, branch `main`, a paid instance (free ones sleep).
- **Build command:**
```bash
pnpm install --frozen-lockfile --prod=false && pnpm --filter @chartnexa/shared-types --filter @chartnexa/design-tokens --filter @chartnexa/api-contracts build && pnpm --filter @chartnexa/api build
```
- **Pre-deploy command (runs the migrations):** `pnpm --filter @chartnexa/api migrate:deploy`
- **Start command:** `pnpm --filter @chartnexa/api start`
- **Health check path:** `/health/ready`

`--prod=false` matters: with `NODE_ENV=production` pnpm would otherwise skip the build tools. If `NODE_VERSION=26.13.1` is not offered by Render, tell me; the repository requires Node 26.

### Environment variables
| Name | Value |
|---|---|
| `NODE_ENV` | `production` (the API refuses to start without it) |
| `NODE_VERSION` | `26.13.1` |
| `TRUST_PROXY` | `true` (Render's proxy; real client addresses for rate limits) |
| `LOG_LEVEL` | `info` |
| `DATABASE_POOL_MAX` | `5` |
| `DATABASE_URL` | Neon **pooled** URL (`...-pooler...?sslmode=require`), secret |
| `MIGRATION_DATABASE_URL` | Neon **direct** URL (`?sslmode=require`), secret. Used only by `migrate:deploy` |
| `CURSOR_SECRET`, `ACCESS_TOKEN_SECRET`, `METRICS_TOKEN` | generated (32+ characters) |
| `STAFF_MFA_REQUIRED` | `false` — owner-approved email/password-only staff sign-in |
| `MFA_ENCRYPTION_KEY` | the base64 value above, secret |
| `STORAGE_DRIVER` / `VIDEO_PROVIDER` / `PAYMENT_PROVIDER` | `postgres` / `direct` / `disabled` |
| `SCANNER` / `FILE_UPLOADS` | `none` / `disabled` (or `clamav` + `CLAMAV_HOST` later) |
| `MAILER_DRIVER`, `RESEND_API_KEY`, `MAIL_FROM` | `resend`, your key, `ChartNexa <hello@your-domain>` |

Never set `MFA_DEV_BYPASS` (the server refuses it in production and on any non-local database) and never set `EXPO_PUBLIC_DEMO_ACCOUNTS`. Nothing in the mobile app is secret: it only knows the public API address.

## Migration procedure
- **First deploy and every later deploy:** the pre-deploy command applies pending migrations (`prisma migrate deploy`, forward-only, using the direct Neon URL) before the new version starts; if it fails, the deploy stops and the old version keeps running.
- **Before a risky migration:** in Neon create a branch or note the restore point (point-in-time restore), because rollbacks are `down.sql` files that are only run by hand, never automatically.
- **Check locally first:** `pnpm --filter @chartnexa/api migrate:roundtrip` (CI runs it).
- **Manual run** (for example from your Mac, with the direct URL): `MIGRATION_DATABASE_URL='<direct url>' pnpm --filter @chartnexa/api migrate:deploy`.

## First Admin
A fresh database has no accounts and no demo data. The demo seed refuses to run in production. In the Render **Shell** for the service (or locally with the production variables set):
1. Create the account in the app (Sign Up) and verify the email.
2. Run `pnpm --filter @chartnexa/api admin:bootstrap -- --email you@example.com` to make it the first Admin.
3. The Admin signs in (email/password only when `STAFF_MFA_REQUIRED=false`) and invites Instructors and appoints Managers.

## Verify the deployment
Replace `$API` with the Render URL (for example `https://chartnexa-api.onrender.com`):
```bash
curl -s $API/health/ready                      # {"status":"ok"}
curl -s -o /dev/null -w "%{http_code}\n" $API/docs      # 404 (API docs are off in production)
curl -s -o /dev/null -w "%{http_code}\n" $API/metrics   # 401 without the token
curl -s "$API/courses?limit=5"                  # {"items":[],...} on a new database
curl -s -o /dev/null -w "%{http_code}\n" -X POST $API/auth/login -H 'content-type: application/json' -d '{"email":"nobody@example.com","password":"wrong-password-1"}'   # 401, never 500
```
Then sign up through the app, check the verification email arrives, and run the Admin steps above. In the Render logs there must be no `SECURITY WARNING` line. In Neon, `SELECT count(*) FROM _prisma_migrations;` shows every migration applied.

## Point the mobile app at it
```bash
npx eas-cli env:create --environment production --name EXPO_PUBLIC_API_BASE_URL --value https://<your-render-host> --visibility plaintext
```
Then continue with `docs/operations/testflight.md`. Emailed links use the `chartnexa://` scheme, so they open the installed app but not from a phone without it.

## Known limits of this pilot setup
No purchases, no lesson-file uploads (until a scanner exists), pilot-scale video, no push notifications, one API instance. Each is a recorded decision; none was weakened to make them work.
