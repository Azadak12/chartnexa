# Design
- **Thumbnails:** bytes in object storage under `thumbnails/<uuid>`, type decided from the bytes (PNG, JPEG, WebP, 2 MB), the id changes on every replace so responses are `immutable`. Courses gain `instructor_id`, `thumbnail_id`, `thumbnail_mime` with CHECKs.
- **Invitations:** table with a partial unique index (one open invitation per address) so duplicates are safe under races; token stored only as a hash; every refusal of an acceptance returns the same message; existing accounts must type their password; managers can change only their own invitations. Deactivation reuses the Admin role locks and last-Admin rules, ends grants and sessions in one transaction, and never deletes courses.
- **Assignments:** recipients table keyed by (assignment, user); a submission needs a recipient row (foreign key); visibility is one query (published, recipient, active entitlement); hand-in is an `INSERT ... ON CONFLICT DO UPDATE ... WHERE status <> 'reviewed'`, so feedback locks the work even under races; attachments reuse signed-link grants bound to the assignment id. The new permission is added to the grants CHECK constraint (found by test: without it, every Instructor course creation would have failed).
- **Seed:** drives the real services (course, lesson, upload, purchase, review, assignment) instead of raw inserts, so validation and invariants apply. Refuses production and non-local databases. Passwords are random, hashed in the database, and written only to a mode-600 ignored file. Admin and Manager keep two-step sign-in.
